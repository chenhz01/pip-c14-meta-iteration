# Learning Cards

Each card has four layers: **L0** a twelve-year-old can follow → **L1** the mechanism → **L2** how to use it → **limit** when it fails. Plus the gap evidence.

---

## 元迭代

> 上面这些判定本身准不准？也该有个东西盯着。

### L52 · 迭代协议编译

`iteration-protocol-compiler` · `components/L52-iteration-protocol-compiler/`

- **L0（人话）** 流程写在脑子里，换个人跑就变形。这工具把流程写成每一步都带「失败时怎么办」的清单。
- **L1（本质）** 每步给 entry / exit / on_fail，缺 on_fail 即判不可执行。可执行性的唯一判据：任何一步失败时，协议本身能说出下一步做什么。
- **L2（怎么用）** 任何多步任务先编译；undefined_failure_handling 为空才开工。
- **边界** 只查每步有没有失败处置，不判处置是否合理。
- **空白证据** 工作流引擎要图/DSL，缺「把自然语言流程编译成带失败处置的协议」的轻量器（抽样未单列）。

### L53 · 复盘模式挖掘

`process-retro-miner` · `components/L53-process-retro-miner/`

- **L0（人话）** 每次都说「下次注意」，但没算过哪个毛病最费时间。这工具算出「先修哪一个」。
- **L1（本质）** 按累计浪费排序（频次×平均浪费在数学上就是累计浪费，不假装是两件事），同额时比频次——常犯的错更好修。输出 top1 占比，决定「修单点」还是「改流程」。
- **L2（怎么用）** 每周挖一次；top1 占比 ≥40% 就集中修它，别同时改五件事。
- **边界** 依赖记录完整；没记录的失败会被系统性低估。
- **空白证据** 回顾会议靠人记忆，缺「从记录里挖出最贵毛病」的量化器（抽样未单列）。

### L54 · 循环模板进化

`loop-template-evolver` · `components/L54-loop-template-evolver/`

- **L0（人话）** 你手上几套做事流程，有好有坏。这工具让好的留下、两两合并，并且只改掉最没用的那一步。
- **L1（本质）** 每轮保留最好的 keep 个 → 交叉（各取一半步骤）→ 小概率变异，且变异只替换出现频次最低的步骤。变异不是乱改：乱改等于随机搜索，替换最弱一步是定向改进。
- **L2（怎么用）** 模板 ≥3 个时才用；分数必须来自实跑，不能自评（否则进化的是自评能力）。
- **边界** 分数必须来自实跑；用自评分会进化出自评能力。
- **空白证据** 进化算法库很多，缺「面向流程模板、只变异最弱步」的轻实现（抽样未单列）。

### L55 · 工具自测

`harness-self-test` · `components/L55-harness-self-test/`

- **L0（人话）** 检查工具的工具，自己也可能坏。它坏了还一直报「通过」，那所有结论都不算数。
- **L1（本质）** 三类自伤：返回 None 却不报错（silent-none）、类型不符（contract）、零断言（fake-green，跑了就算过）。一个工具自己沉默失败时，它报的所有绿灯都不可信。
- **L2（怎么用）** 每月审计一次 harness；fake-green 是最高优先级——它比没有测试更危险。
- **边界** 只能发现三类自伤；逻辑错误它看不见。
- **空白证据** 测试框架管被测代码，缺「审计审计器本身」的原语（抽样 179 条属大类拥挤，本件只做窄口）。
